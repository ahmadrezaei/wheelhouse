# Wheelhouse — Architecture (foundation)

Design source of truth: `design/DESIGN.md` (§2 navigation, §5 states, §7 safety, §8 design system, §13 tech). This file lists the **stable APIs** feature engineers build on.

### Building and testing on macOS
`WheelhouseKit` and `WheelhouseUI` build for macOS 27 as well as iOS 27, so the Kit suite runs on the Mac host, with no simulator (and without its `~/Documents` hang):
```
cd Packages/WheelhouseKit
swift build            # Kit and UI for the host Mac (arm64, macOS 27)
swift test             # whole Kit suite; about 13 s of test time, plus the first build
```
`WidgetRenderTests` (UIKit `ImageRenderer.uiImage`, lock-screen accessory views) is compiled for iOS only, so it runs only in the simulator `xcodebuild test` above. AppKit/UIKit differences in WheelhouseUI go through `Sources/WheelhouseUI/Platform/` (modifiers such as `whInlineNavigationTitle()`, `Pasteboard`, `Haptics`, `Color.whCardBackground`); do not add `#if os(...)` at call sites. Vendored SwiftTerm (plugin-free) lives in `Packages/Vendor/SwiftTerm` (`swift build` / `swift test` there; refresh with `scripts/vendor-swiftterm.sh`, verify with `--check`). The macOS app itself arrives in milestone M1a; see `design/mac/ARCHITECTURE-MAC.md`. Perf baselines: `perf/baselines/<milestone>.json`.

**Run `test` with a derived-data path outside `~/Documents`** (e.g. `-derivedDataPath /tmp/wh-dd-test`): the simulator test host hangs forever on `opendir` of bundles under `~/Documents` (macOS privacy prompt it cannot show); `build` is unaffected. Use your own `-derivedDataPath` (e.g. `.build/dd-<feature>`) when building in parallel. Never point tools at `~/.kube`; use Demo mode or the dedicated test cluster.

## Kit core APIs
- **`KubeClientProtocol`** (Sendable): `version()`, `discovery()`, `list/get<T: KubeObject>`, `listRaw/getRaw(kind,…) -> JSONValue`, `watch<T>(…) -> AsyncThrowingStream<WatchEvent<T>,Error>`, `create/replace/patch/delete`, `logs(namespace:pod:options:) -> AsyncThrowingStream<String,Error>`, `podMetrics/nodeMetrics`, `proxyGET(namespace:service:port:path:query:)`, `execWebSocket/portForwardWebSocket -> KubeWebSocket` (wrapper over `URLSessionWebSocketTask`; you implement channel protocols). Extensions: `scale`, `restartRollout`, `setCronJobSuspended`, `setNodeUnschedulable`, `evict(pod:)`. Patches: `KubePatch.merge/.strategicMerge/.json/.apply` (SSA uses fieldManager `wheelhouse`, `MutationOptions(dryRun:force:)`). **Dry-run wire format**: kube-apiserver decodes `DeleteOptions` from the request body and IGNORES the `?dryRun=All` query when a body is present, so `delete` with `dryRun` puts `"dryRun": ["All"]` in the body AND keeps the query; `evict(pod:…dryRun:)` sets `deleteOptions.dryRun` in the Eviction body AND the query. create/replace/patch/apply bodies are the object itself (no options), so the query parameter is the only carrier there and is honoured. Regression tests: `DryRunBodyTests` (URLProtocol capture through the internal `LiveKubeClient(…protocolClasses:)` initialiser).
- **`LiveKubeClient`** (actor) – URLSession + per-cluster delegate: custom CA anchors, skip-TLS (**ignored for production**, see `ClusterConfig.allowsInsecureTLS`; `ClusterConfig.tlsServerName` (kubeconfig `tls-server-name`, optional Codable) is the name the certificate is validated against, passed to `LiveKubeClient(config:secrets:tlsServerName:)` by the registry's client factory), client-cert identity (PEM → key + cert added to the keychain as ThisDeviceOnly items, identity queried back; see `ClientIdentityBuilder`), bearer token. **Read-only clusters throw `KubeError.readOnly` before any request** (also exec/port-forward unless `allowExecInReadOnly`).
- **Ordered stdin queue** (`ExecSession` / `OrderedFrameWriter`): `ExecSession.send(_:)` and `resize(cols:rows:)` are `nonisolated` and synchronous; they only `yield` an encoded frame into an unbounded `AsyncStream<Data>`, and one long-lived consumer task (started in `start`, cancelled in `close`/`finish`/`deinit`) awaits each `ws.send` before the next. The initial resize frame goes through the same queue and its completion is the `.opened` signal. Never write to the socket from per-keystroke `Task`s or from an actor method: actor reentrancy reorders them (`echo abcdef…` arrived as `echoabcdef ghi…`). `ShellModel.terminalSurface(_:send:)` therefore calls `exec.send` directly. The port-forward tunnel has a single sequential reader→`ws.send` loop per direction and is already ordered. Regression tests: `OrderedFrameWriterTests`.
- **`DemoKubeClient`** – same protocol, in-memory fleet (`DemoFleet.configs`: prod-eu-west *production*, staging, homelab-k3s, edge-oslo *unreachable*). Mutations really change state; watches emit simulated updates; exec/port-forward throw `.unsupported`.
- **`KubeError`**: `unreachable, tlsUntrusted, unauthorized, forbidden(verb,resource,namespace,message), notFound, conflict, invalid(message,causes), readOnly, gone, server(Status), decoding, unsupported, cancelled`; `.summary`, `.isTransient`. `EmptyStateKind(error:)` (UI) maps errors to screens.
- **`ResourceKind`** registry: statics (`.pod`, `.deployment`, …), `ResourceKind.builtIn`, `.builtIn(in: section)`, `.lookup("deploy…")`, `.custom(group:version:kind:plural:namespaced:)`, `collectionPath(namespace:)`, `itemPath(name:namespace:subresource:)`, `.symbol`, `.displayName`, `.section`. `ResourceRef(clusterID, kind, namespace, name)` identifies any object (Codable/Hashable).
- **Models**: `Pod Deployment StatefulSet DaemonSet ReplicaSet Job CronJob Service Ingress NetworkPolicy Endpoints EndpointSlice ConfigMap Secret PersistentVolume(Claim) StorageClass Node Namespace KubeEvent EventsV1Event CustomResourceDefinition ServiceAccount Role ClusterRole RoleBinding ClusterRoleBinding PodDisruptionBudget NodeMetrics PodMetrics Status`, `KubeList<T>` (skips undecodable items, `skippedItems`), `Unstructured` (any kind + `raw: JSONValue`), `JSONValue` (literals, `value(at:"a.b")`, `setValue`), `Quantity` (`cores`, `millicores`, `bytes`, `formatBytes`). Missing collections decode as empty (`@Lenient`). Use `KubeJSON.decoder`.
- **`ClusterRegistry`** (`@MainActor @Observable`, in the environment): `clusters`, `currentCluster/currentSession/currentClusterID`, `namespace(for:)`/`currentNamespace` (**nil = All namespaces**), `session(for:)`, `add/update/remove`, `enterDemoMode()/exitDemoMode()`, `refreshAllHealth()`, `fleetAttention`, `makeSnapshot()`.
- **`ClusterSession`**: `client`, `config`, `connection`, `version`, `latency`, `health`, `metricsAvailability`, `refreshHealth()`, `detectMetrics()`, `loadDiscovery()`, `metrics: MetricsService`, **`store(for:namespace:labelSelector:fieldSelector:)`**.
- **`ResourceStore<T>`** (list → watch → relist on 410, ref-counted, 10 Hz coalescing, cached items kept when stopped; **`pause()`/`resume()`** cancel and restart the watch while keeping consumers registered (used when the app backgrounds: `registry.stopAllSessions()` pauses, `resumeAllSessions()` resumes on `.active`); **`invalidate()`** cancels and drops all consumers when a cluster is removed or its credentials/config are replaced; `cancel()` is an alias):
```swift
struct PodsView: View {
  let session: ClusterSession; let ns: String?
  var body: some View {
    let pods = session.store(for: Pod.self, namespace: ns)          // shared instance per key
    List(pods.items) { PodRow($0) }
      .overlay { if pods.isLoading { EmptyState(.loading) } else if let e = pods.error, pods.items.isEmpty { EmptyState(EmptyStateKind(error: e)) } }
      .refreshable { await pods.refresh() }
      .task { await pods.run() }                                    // start/stop tied to the view
  }
}
```
  Custom resources: `session.unstructuredStore(kind:namespace:)`. Sorting: `store.sortOrder = { … }`.
- **`ClusterEvents`** (Kit): `registry.update/remove` post `ClusterEvents.invalidated` (`postInvalidated(id, removed:)`; read with `clusterID(from:)` / `wasRemoved(_:)`) and call `LiveKubeClient.invalidate()`. Long-lived holders (port-forwards, shells, log streams, open screens) observe it and drop anything bound to the old client/config. Mutations re-check the live config (read-only, environment) before running.
- **Missing credentials**: `ClusterSecrets.isMissingCredentials(for:)`. When true the registry never caches the session (only a short-lived transient one) and sets `ClusterSession.credentialsMissing`; the cluster dashboard and fleet `ClusterCard` then show "Credentials not on this device" with an **Edit Cluster** action instead of unreachable/unauthorized. Registry `update` also re-saves the Prometheus token (`PrometheusTokenStore`) when the iCloud flag changes; `remove` deletes it.
- **iCloud sync compatibility (never lose what this build cannot read)**: the synced cluster mirror (`ClusterMetadataStore.Mirror`, JSON object `{clusters, deleted}` or the legacy bare array) is written by several app versions and platforms, so older installs must tolerate newer data. Rules: (1) the mirror is decoded **per element** (`RawJSON` splits the exact bytes); one bad element never costs the others. (2) An element that fails to decode (new enum case, changed field type, new element type) is kept as a **raw** element and written back **byte for byte**; tombstone values that are not dates and unknown top-level keys are preserved the same way. (3) Same id both raw and decoded: the newer `modifiedAt` wins; on a tie or when the raw date/id cannot be read the **raw copy wins** (an older decoded copy is hidden on load and never tombstoned); a raw element with no readable id is always kept; tombstones still remove raw elements they are newer than. (4) A mirror that is not parseable JSON at all is never overwritten (local `clusters.json` is still saved); an unparseable local file is copied to `clusters.json.unreadable` first. Local `clusters.json` also keeps raw elements it cannot decode. (5) `ClusterConfig` / `ClusterSecrets` ignore unknown keys but keep them in `unknownFields` and re-encode them. Unknown values of `environment` and `authKind` are **not** mapped to a guess: the decode fails so the element stays raw (hidden on this device, never treated as less safe, never edited); only the cosmetic `color` falls back to gray and keeps its raw string until the user picks a colour. (6) Keychain items (`ClusterSecrets`, Prometheus token) that fail to decode are "unreadable here": never overwritten (`KeychainError.unreadable`) and never deleted. (7) New fields must be optional or have a fallback, new enum cases must be assumed unknown to older builds, and `Tests/.../Frozen_1_0_1.swift` (a copy of the 1.0.1 decoder) must keep reading whatever the current code writes (`SyncCompatibilityTests`). (9) A mirror read that FAILS (locked keychain, `errSecInteractionNotAllowed`, ...) is never an empty mirror: `MetadataMirroring.read()` throws, `readMirror()` maps only item-not-found to an empty `Mirror` and any other error to an opaque one, which `save()` never replaces. (10) A local copy hidden by a newer raw mirror copy is kept in `clusters.json` (hidden, not deleted), so it reappears if the raw copy vanishes without a tombstone; a cluster deleted in the same session a raw twin arrives for stays hidden and is not tombstoned (the raw copy belongs to a newer app). Local raw elements whose id is already written are dropped (no duplicate ids), and a raw mirror copy older than a decoded copy of the same id is dropped even without a local copy. (11) "Unreadable" is checked across BOTH keychain variants (`KeychainBackend.readAll`, device-only and synchronizable): if any variant fails to decode, nothing is overwritten or deleted. A cluster with unreadable secrets stays editable (`AddClusterView` passes `secrets: nil` when unchanged) and its session shows `credentialsProblem` instead of "unauthorized". An unparseable local `clusters.json` is backed up first with a failing copy aborting the save (`clusters.json.unreadable`, then `.unreadable-<epoch>`). (12) **Rules for future formats**: a new safety restriction must be expressed through existing required fields (`readOnly`, environment production) or a required-key change, never only through a new optional key (older builds ignore unknown keys and would drop the restriction). New-format elements from future versions or the Mac app go under a NEW keychain account (e.g. `clusters.v2`); only elements that 1.0.1 can decode stay in the existing `app.wheelhouse.sync/clusters` mirror, because builds 5 and earlier still wipe a mirror containing anything they cannot decode. A new Prometheus token format needs a new service name (`app.wheelhouse.prometheus` stays UTF-8 only). (8) `KeychainAccess.baseQuery(accessGroup:)` / `SystemKeychain.accessGroup` default to the shared group `<TeamPrefix>.com.ahmadrezaei.wheelhouse.shared`; an optional Info.plist key `WHKeychainGroupSuffix` replaces only the suffix (iOS targets do not set it).
- **TLS** (`Client/TLSDelegate.swift`): `ClusterSessionDelegate` evaluates server trust through `TLSValidator.evaluate(trust, host:, anchors:)` using the custom CA anchors and `tlsServerName ?? host` as the name; failures are recorded as `TLSFailureInfo` (subject, SHA-256) for the TLS error screen. Skip-verify is honoured only for non-production clusters. Server trust is approved ONLY by `TLSValidator` (or the explicit non-production skip-verify); no other path returns a trust credential. A client-certificate challenge with no `identityProvider` (token cluster) is declined without recording a failure (`clientCertificateMissing` is only a hint for `.clientCertificateRequired` / -9863); the identity sign-test is diagnostic only (the identity is always presented; the result is `identityNote`, appended to a 401). `TLSTrace` (non-secret challenge/identity/error-chain facts) feeds the copyable report (`ConnectionDiagnosticsReport`, available from the Add Cluster card and each Import row). **Session-level trust rejections**: URLSession delivers server-trust challenges to the session delegate (`urlSession(_:didReceive:)`) with no task URL, so `ClusterSessionDelegate` records the rejection by `host:port` (plus a "most recent" slot), valid for 60 s and cleared by the next successful evaluation. `failure(for:)` matches a request URL by exact URL, then by `host:port`, and (for an unknown URL) by recency. A rejected challenge surfaces from URLSession as `-999` (`.cancelled`); `LiveKubeClient.mapTransportError` maps that to `.tlsUntrusted(summary:)` when a rejection was recorded (or the trace says trust failed), and only to `.cancelled` for real cancellation. `ClusterSession.refreshHealth` treats `.cancelled` as task cancellation only when `Task.isCancelled`; any other failed probe (including a stray `.cancelled`) marks the cluster unreachable, and the cluster dashboard shows the TLS empty state for `connection == .failed(.tlsUntrusted)` instead of a skeleton. Transport errors on a task that already got a response (streams, WebSocket after upgrade) map to `.unreachable`, never `.tlsHandshake`.
- **ATS**: the app target sets `NSAppTransportSecurity = { NSAllowsArbitraryLoads: true }` and deliberately NOT `NSAllowsLocalNetworking` (iOS ignores `NSAllowsArbitraryLoads` when it is present). Reason: ATS runs its own system trust evaluation for non-local hosts and rejects the private CAs of user-specified API servers even though `ClusterSessionDelegate` approved the trust. Compensating controls: strict in-app validation (above), `LiveKubeClient.guardTransport` refuses `http://` for production clusters (REST, watch, logs, exec/port-forward WebSockets), `PrometheusClient` refuses a non-https direct URL for production clusters, and `ClusterRules.violatesHTTPProductionRule` blocks saving one. Plain HTTP is only used for non-production clusters and the in-app port-forward `WKWebView` to `http://127.0.0.1`. App Review text: `docs/AppReviewNotes.md`.
- **`DeepLink`** (Kit/Models): pure parser/builder for `wheelhouse://cluster/<id>[/ns/<ns>][/<kind>/<name>][?view=logs|yaml…]` with `KubeNames` validation of every segment; `view=shell` is deliberately unsupported (a link must never start exec). The App target maps it to a `Route` in `DeepLink+Routes.swift`.
- **`SecretRevealGate`** (Kit/Preferences): honours `revealSecretsOncePerSession` for Secret reveal (Resources Secret detail, YAML editor reveal/edit); reset whenever `AppLockController.isLocked` becomes true. Copying a secret always authenticates.
- **Health** (pure, unit-tested): `HealthEvaluator.evaluate(ClusterHealthInput) -> ClusterHealth` (status, `items: [AttentionItem]`, counts), `Pod.stateSummary()`, `PodDiagnoser.diagnose(pod, memoryPeakBytes:) -> PodDiagnosis?` (banner text), `HealthStatus` (healthy/warning/critical/unknown).
- **Metrics**: `MetricsAvailability`, `MetricsService.availability()`, `PrometheusClient.queryRange(PromQL.*, name:, range:) -> [TimeSeries]`, `MetricsRange`.
- **Other**: `KubeconfigParser.parse(text) -> Kubeconfig` (contexts with `status`, `unsupportedReason`, `makeClusterConfig()`), `KubeconfigParser.serviceAccountTokenCommands()`, `KeychainCredentialStore`, `ClusterMetadataStore`, `FleetSnapshot` + `WidgetDataStore`, `AppPreferences` (App Group defaults, in the environment), `AppGroup`. `ClusterRegistry.onFleetShrank` (set by the app) prunes the removed cluster (or the Demo fleet on exit) from the widget `fleet-snapshot.json` and reloads timelines. Privacy manifests: app (UserDefaults CA92.1 + 1C8F.1, file timestamp C617.1), widgets (UserDefaults 1C8F.1), share extension (its own `PrivacyInfo.xcprivacy`); none declares tracking or collected data.

## Energy & log streams
- **`EnergyPolicy`** (Kit/Energy): `EnergyPolicy.current` (Low Power Mode + `ProcessInfo.thermalState`) → `refreshMultiplier` (2× Low Power, 2×/4× thermal serious/critical), `interval(_:)`, `allowsLiveCharts`, `allowsLiveSampling`, `suspendsHiddenWatches`, `publishInterval`. `EnergyMonitor.shared` (observable) follows `NSProcessInfoPowerStateDidChange` / thermal changes and posts `EnergyPolicy.didChange`; the app calls `registry.applyEnergyPolicy()` (pauses other clusters' watches while hot). Every poller/auto-refresh scales its interval with `EnergyPolicy.current.interval(base)`. Do not add `repeatForever`/endless symbol effects or 1 Hz timers; prefer Observation-driven updates (see `ClusterDashModel.pollStores`).
- **Log streams**: each `follow=true` request makes the kubelet create an inotify watcher, so `LogStream` keeps ONE follow per pod/container (`LogFollowRegistry`, scoped by cluster id) and at most `maxConcurrentFollows` (6) overall, closing the older stream first; reconnects use `LogReconnectBackoff` (1, 2, 4 … 30 s, give up after 8 short-lived connections); streams are suspended (`LogPauseReason`) when the app backgrounds or the Logs screen is left (unless pinned). If a follow ends with the kubelet's "failed to create fsnotify watcher: too many open files" (`LogStreamProblem`), the stream stops following and polls `…/log?sinceTime=…` (`LogPollDeduper`, `LogStream.mode == .polling`); `LogsView` shows the inotify fix banner with the node name.

## Conventions
- Swift 6 language mode, strict concurrency complete. Stores/sessions/registry are `@MainActor`; clients are actors/Sendable. No force unwraps on network data.
- **All mutations go through `ConfirmSheet`** (dry-run first via `MutationOptions(dryRun: true)` / `DeleteOptions(dryRun: true)`; a `dryRun:` closure must only ever call the client with the dry-run flag, never a real mutation). Undo from an action toast goes through `ActionHost.queue`, which waits for any dismissing sheet before presenting the new `ConfirmRequest`. Production: **every** mutation requires typing the confirmation text (`ConfirmRequest.requiresTyping(for:)`, evaluated against the live cluster config; unknown cluster defaults to requiring it). The single exception is **opening a shell** (`ExecTerminalView`): it sets `ConfirmRequest.typeToConfirmOnProduction = false`, so on Production the sheet still shows the warning, facts and `pods/exec` access review but confirms with an "Open Shell" button, no typing (`alwaysRequireTyping` would still win). Read-only clusters: **hide** mutating UI (`cluster.readOnly`), the client refuses anyway.
- Never log or persist Secret values; reveal behind `AppLockController.authenticate`. Never read `~/.kube` or use real credentials in tests; use Demo / `InMemoryCredentialStore`.
- Put shared additions in your own feature folder; need a new `Route` or shared API? Ask the foundation owner.

## Share extension (WheelhouseShare)
`com.apple.share-services`, principal class `ShareViewController` hosting SwiftUI `ShareView` (no storyboard); activation rule is a SUBQUERY accepting items with at least one attachment conforming to `public.data` or `public.text` and not `public.image` / `public.audiovisual-content` / `com.adobe.pdf` (a caption item next to the file is tolerated; the first matching attachment is used). The extension has no App Group entitlement (keychain access group only) and purges an expired pending item when it starts; it sets `isModalInPresentation`. It loads the item (file URL, then file/data, then plain text) through `SharedAttachment` (Kit: 1 MB cap, UTF-8), parses it with `KubeconfigParser` and shows the contexts. **Import in Wheelhouse** saves it via `PendingKubeconfigStore` (Kit/Onboarding): ONE generic-password keychain item (service `com.ahmadrezaei.wheelhouse.pending-kubeconfig`, shared access group, `AfterFirstUnlockThisDeviceOnly`, never synchronizable) holding text + file name + timestamp; never a file in the App Group. If notification permission is already granted (never requested there) it posts "Kubeconfig ready to import" with `userInfo["url"] = wheelhouse://import`. Share extensions cannot open the app, so the user opens it themselves.
App side: `SceneRoot.openSharedKubeconfigIfAny()` runs when the scene becomes active, after unlock, and on the `wheelhouse://import` link (`DeepLink.isImport`; replayed after unlock like other pending URLs). It `take()`s the item (deleted on read; > 1 hour old = dropped silently; also purged by the extension on start), calls `KubeconfigInbox.offer(text:name:)` (bumps `revision`, which `KubeconfigImportView` observes even when already on screen) and pushes `.importKubeconfig`. DEBUG only: launch with `-WHPendingKubeconfig <path>` to write the pending item without the share sheet.
