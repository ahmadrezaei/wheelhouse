Rigging pack reference

Planned format, not in this release; subject to change. Nothing on this page can be used yet. It is a draft of the design and will be updated when Rigging ships.

A Rigging pack teaches Wheelhouse about a set of custom resources: how to show them, what their status means, which commands to offer and when to raise an alert. A pack is data only. It is a folder with a rigging.yaml file and optional icons.

What a pack can and cannot do

  • It can describe views, commands and health rules.
  • It cannot run code, make network calls, read files, or call the cluster API.
  • Its commands are text that is inserted into a guarded Deck Terminal on the command’s own cluster. You press Return. A port-forward command uses the normal port-forward rules and confirmations.
  • Anything in the file that is not in the format below is rejected when the pack loads, not evaluated later.

Example

apiVersion: rigging.wheelhouse.app/v1
kind: Pack
metadata:
  name: cert-manager
  version: 1.2.0
  description: "Certificates and issuers"
views:
  - match: { group: cert-manager.io, kind: Certificate }
    columns:
      - { name: Ready, path: ".status.conditions[?(@.type=='Ready')].status" }
      - { name: Expires, path: ".status.notAfter", format: age }
    status:
      - { when: { condition: Ready, status: "False" }, tone: critical }
      - { when: { path: ".status.renewalTime", exists: true }, tone: healthy }
    related:
      - { kind: Secret, nameFrom: ".spec.secretName", label: "TLS secret" }
commands:
  - title: "Renew certificate"
    for: { group: cert-manager.io, kind: Certificate }
    terminal: "cmctl renew {{name}} -n {{namespace}}"
  - title: "Open Grafana"
    portForward: { service: grafana, namespace: monitoring, port: 3000, open: "http://127.0.0.1:{{localPort}}/" }
healthRules:
  - for: { group: cert-manager.io, kind: Certificate }
    when: { condition: Ready, status: "False", for: 1h }
    tone: warning
    message: "Certificate {{name}} is not ready"

Top level

KeyMeaning
apiVersionAlways rigging.wheelhouse.app/v1.
kindAlways Pack.
metadataname, version and description. The name identifies the pack in Settings and in Activity.
viewsHow to show a kind of custom resource.
commandsMenu, Rail and Compass entries.
healthRulesConditions that raise an alert.

The file is checked against a schema bundled in the app. A file that does not match is refused with the reason.

Views

A view applies to one resource kind, named by match (group and kind). It reuses the data Wheelhouse already watches; a pack never starts its own watch.

  • columns: a name, a path and an optional format (such as age).
  • status: rules read top to bottom; the first match sets the tone (healthy, warning, critical or unknown). A rule tests a condition type and status, or a path that exists or equals or contains a value.
  • related: objects to link to, found by a name stored in a field (nameFrom), with a label.

Paths (a JSONPath subset)

Paths use a deliberately small subset. Nothing else is accepted.

FormExample
Dot path.spec.secretName
Index.status.addresses[0].ip
Every element.spec.listeners[*].name
Equality filter.status.conditions[?(@.type=='Ready')].status

There are no script expressions, no functions and no arithmetic.

Commands

A command has a title, a target (for: a group and kind) and one action.

  • terminal: a command line template. It is inserted into a guarded Deck Terminal on the same cluster and never run for you.
  • portForward: a service, namespace and port to forward, and an optional open address using {{localPort}}. Ports below 1024 are never offered, and the usual port-forward rules apply.

Templates and quoting

Only a fixed list of variables can be used in {{ }}: name, namespace, cluster, kind, localPort, and fields the pack’s view declares. Anything else is an error. Every value placed into terminal text is wrapped in single quotes with embedded quotes escaped, and names are checked against Kubernetes naming rules where they apply, so a resource called x; rm -rf ~ becomes one harmless argument. Hidden and direction-changing characters are removed again just before insertion.

Health rules

A rule names a kind (for), a condition (when, with an optional for duration such as 1h), a tone and a message template. Matching objects appear in Alerts like any other finding.

Where packs come from

  • Built in: cert-manager, Karpenter, KEDA, External Secrets, CloudNativePG, Istio, Velero, Gateway API.
  • A local folder. Symbolic links and paths containing .. are rejected.
  • A git address. Cloned with your own git into the app’s folder and pinned to the commit you see. It never updates by itself.

Before you turn a pack on, Settings shows everything it declares: its source, its commit, and each view, command and rule it adds. There is no hosted catalogue. Turn a pack off, or remove it, at any time.

Where it shows up

  • In the resource tables and detail views for the kinds it covers.
  • In the right-click menu for those resources, in the Rail and in Compass (commands).
  • In Alerts (health rules).
  • In Activity, with the pack’s name as the origin, if one of its actions leads to a confirmation.
