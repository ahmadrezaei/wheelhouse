Wheelhouse for Mac

Feature guide

The Mac app has everything the iPhone and iPad app has, plus the features below. Each section says what the feature does and what it will and will not do on its own.

  • Deck Terminal and Gangway
  • Chart Room
  • Survey
  • Tides
  • Landfall
  • First Mate
  • Beacon
  • Compass and the Rail
  • Crow’s Nest
  • Rigging

Deck Terminal and Gangway

A Deck Terminal is a real shell (your own $SHELL) where kubectl, helm, k9s, stern, flux and kubectl plugins work against the cluster of the pane you opened it from. Press Control-backtick for a drawer at the bottom of the pane, or Shift-Control-backtick for a new terminal pane.

Gangway is what makes that safe. The terminal does not get your real kubeconfig. It gets a temporary one that points at a small proxy inside Wheelhouse on 127.0.0.1. The proxy applies the same rules as the app: read-only clusters refuse changes, and on Production a change waits for your confirmation. Details are on the security model page.

  • A Production terminal shows a banner you cannot dismiss: “kubectl and helm changes need confirmation”.
  • If a command tries to bypass the guard (for example with --kubeconfig), the pane says Unguarded.
  • Text that Wheelhouse inserts for you (from First Mate, Rigging or Copy kubectl Command) is placed at the prompt and never run. You press Return.
  • Scrollback is 5,000 lines by default (up to 20,000). Closing a pane with a running command asks first.

Chart Room

Helm releases, charts and repositories. Releases are read directly from the cluster, so the list is quick. Install, upgrade, roll back and uninstall run Helm (bundled, or your own version 3.14 or later) through the same Gangway guard, after a review that shows the exact objects that will change and, for Production, a typed confirmation.

  • Failed and pending releases are pinned to the top.
  • Compare revisions, show values and the manifest, and see whether live objects have drifted from the release.
  • A badge shows when Flux or Argo CD manages a release, so you do not fight your GitOps tool.

Survey

A security center for your fleet: vulnerabilities, configuration problems and access risks, from the fleet down to a single image. It reads Trivy Operator reports if the cluster has them, can scan images on your Mac with Trivy when you press Scan Now, and applies built-in rules to RBAC and pod specs.

  • Scanning is optional and only starts when you ask. A Trivy download needs your approval and is checked against a checksum.
  • Secret values are never read by Survey. Exports contain findings, not secrets.

Tides

GitOps for Flux and Argo CD. Tides appears in a cluster’s sidebar only when the cluster has those tools installed. You get an overview of what is out of sync, degraded, suspended or failing, with the target and live revision side by side, and a detail view for each app.

  • Sync, reconcile, suspend and resume go through the normal confirmation.
  • Flux diff compares a Flux Kustomization with a local folder you choose. It runs in a dry-run-only guarded session, so it cannot change the cluster.

Landfall

Finds your managed clusters (Amazon EKS, Google GKE, Azure AKS) using the command-line sign-in you already have, and adds them with one click. Wheelhouse starts your own aws, gcloud or az and never stores your cloud passwords. The added cluster uses the same command to get short-lived tokens. You can scan once or choose a daily rescan; a rescan never adds a cluster by itself.

First Mate

A chat assistant that knows which object you are looking at, reads cluster state, explains failures and drafts YAML and commands. It uses your own Anthropic API key and is off until you add one. It never changes anything itself: a change it proposes opens the normal review and confirmation, and a command it proposes is inserted into a terminal for you to run.

  • Secret values are never read or sent. Tokens, keys and certificates are replaced with a marker before anything leaves your Mac.
  • You can see exactly what was sent for each message.
  • Production clusters ask your permission first, per conversation. You can set any cluster to Never.
  • You can set a cost limit per conversation and per day.

Beacon

A built-in MCP server that lets AI agents you already use (such as Claude Code or Claude Desktop) read cluster state through Wheelhouse, with Wheelhouse’s redaction and safety rules. It is off by default, and turning it on asks for Touch ID or your password every time.

  • It works over a local connection only, between a small helper and the app. There is no network listener.
  • Each client you approve gets its own secret. You can see and stop clients in Settings and in Crow’s Nest.
  • An agent can read. Anything that would change a cluster goes through the same confirmation as your own actions, and you are the one who confirms it.

Compass and the Rail

Compass (Command-K) is one search field for everything: menu actions (with their shortcuts), resources, clusters and namespaces, Helm releases, GitOps apps, layouts, settings and help. It understands short names (po, deploy), fuzzy and acronym matching, and puts problems first. Press Return for the default action, or the right arrow for more. Compass never runs a change directly: a mutating action opens the confirmation sheet. Typing ! first runs the text you typed in a terminal, and nothing else ever runs in a terminal on your behalf.

The Rail (Shift-Command-B) is a strip of pinned items: clusters, resources, saved layouts (Stations), namespaces and Rigging commands. Drag anything onto it, or use Option-Command-B. Clicking a cluster switches the focused pane to that cluster and keeps the current view. The Rail and Stations stay on this Mac.

Crow’s Nest

The menu bar item. Its icon shows a small dot when something needs attention (orange for warning, red for critical). The panel lists what needs attention, each cluster’s health, your active sessions (port-forwards, terminals) and Beacon’s state, with a one-hour pause for checks.

  • Turn on Keep running in the menu bar to keep monitoring after you close the last window. The Dock icon is hidden in that state.
  • Health checks run about once a minute for Production and Staging clusters and the ones you add to the Rail or opt in. With no window open, checks are small probes, and a full evaluation runs every few minutes. Low Power Mode halves the pace.
  • Notifications use the same rules as iPhone: crash loops, node not ready, failed jobs, expiring credentials, plus Mac extras such as a failed Helm release. They never offer a button that changes a cluster.
  • The desktop widgets follow these checks: the snapshot is refreshed only when something changed, and at most every five minutes.

Rigging

Rigging adds knowledge of extra resource types, and shortcuts for them, using packs: plain data files, never code. A pack can add columns and status colours to a custom resource, link related objects, add commands, and add health rules. Wheelhouse ships packs for cert-manager, Karpenter, KEDA, External Secrets, CloudNativePG, Istio, Velero and the Gateway API.

  • A pack command is inserted into a guarded terminal on the right cluster. You press Return.
  • A pack cannot run code, use the network, read files outside its folder or call the cluster API.
  • You can add your own pack from a folder, or from a git address (cloned with your own git, pinned to a commit, updated only when you ask). You see everything the pack declares before you turn it on.

The file format is described in the Rigging pack reference.
