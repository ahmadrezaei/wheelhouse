Wheelhouse for Mac

Getting started

This page takes you from a fresh install to a first look at your clusters. Wheelhouse talks directly to your clusters’ API servers. There is no account to create and no server run by the developer in between.

What you need

  • An Apple silicon Mac running macOS 27 or later.
  • At least one Kubernetes cluster you can reach, and a kubeconfig or a token for it. No cluster? Use the demo fleet (below).
  • Optional tools Wheelhouse can use if you have them: kubectl, helm (a recent one is bundled), flux, trivy, git, and the AWS, Google Cloud or Azure command-line tools.

1. Install

Open the downloaded disk image and drag Wheelhouse to Applications. The app is signed and notarized. Updates arrive inside the app (Wheelhouse, Check for Updates), and you can turn the daily check off in Settings.

2. Add your clusters

On first launch Wheelhouse offers to look for kubeconfig files on your Mac (this is Moorings). It shows what it found and asks before importing anything. Clusters found this way start read-only: you can look, but changes are refused until you allow them for that cluster in its settings.

  • Import a kubeconfig file, or paste an API server address with a service-account token.
  • Cloud clusters: Landfall lists the EKS, GKE and AKS clusters your own command-line sign-in can see, and adds them in one click.
  • Mark production clusters as Production. They get a rose banner and every change needs a typed confirmation.
  • No cluster yet? Choose Explore Demo to try a simulated fleet.

3. Find your way around

WhereWhat it is
SidebarEach cluster and its resource kinds. Kinds you cannot read are hidden unless you ask to see them.
Tabs and panesCommand-T opens a tab, Command-D splits the focused pane. Everything restores when you relaunch.
RailThe strip under the toolbar for pinned clusters, resources and layouts. Command-1 to Command-9 jump to the first nine items; Command-0 is always the Fleet.
CompassCommand-K. Search resources, run any menu action, jump to a cluster or a Helm release.
Crow’s NestThe menu bar item with the fleet summary. It can keep running when you close the last window.
InspectorDetail, events and First Mate for the selected object.

4. A first five minutes

  1. Open the Fleet (Command-0) and see which clusters need attention.
  2. Click a failing pod, open its logs, and read the events.
  3. Press Control-backtick to open a terminal drawer for that cluster. Run kubectl get pods. The terminal is already pointed at the cluster, through the guard described in the security model.
  4. Press Command-K and type part of a pod name to jump to it.

Widgets

Wheelhouse provides a Fleet Health widget and a Cluster widget in small, medium and large sizes. Add them from the desktop or Notification Center (Edit Widgets). They show a summary the app writes while it is running: cluster names, health, counts and usage fractions. They never hold credentials or Secret data and never connect to a cluster themselves. A widget shows “Updated N min ago” and dims when the data is old; open the app to refresh it.
