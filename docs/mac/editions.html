Wheelhouse for Mac

Two editions of Wheelhouse for Mac

Wheelhouse for Mac comes in two editions. Both are free, both talk directly to your clusters with no account, no backend and no analytics, and both are built from the same source code.

  • Open-source edition. A signed, notarized disk image from GitHub. It has all the features in the table below and updates itself.
  • App Store edition. Coming to the Mac App Store. It runs inside the macOS App Sandbox, so a few features that need to start other programs are left out. The App Store updates it.

Pick the open-source edition if you use EKS, GKE or AKS with their command-line sign-in, want a terminal, or install Helm charts from Wheelhouse. Pick the App Store edition if you prefer a sandboxed app with App Store updates and your clusters use tokens or certificates.

Why the App Store edition does less

Every app on the Mac App Store must run in the App Sandbox. The sandbox keeps an app inside its own container. By default it cannot read your home folder, and it cannot run programs that are not part of macOS or the app itself.

Several Wheelhouse features rely on exactly that: the terminal runs your shell, Helm and Trivy are separate programs, Landfall and exec-plugin sign-in call aws, gcloud and az, and Beacon is a helper that other tools start. In the sandbox these cannot work, so the App Store edition does not include them, and says so where they would be. It does not download or run extra code to get around this.

The open-source edition is not sandboxed. It is protected by the same guards (read-only clusters, confirmation for Production) described on the security model page.

Granting access to your .kube folder

The sandbox hides ~/.kube until you say otherwise. In the App Store edition, open Settings, Moorings and choose Grant .kube Folder…. Wheelhouse shows a standard macOS open panel to choose your .kube folder. You can also import a single kubeconfig file from the Welcome screen or the File menu. It remembers the choice and only reads inside that folder. It will not accept your whole home folder.

Other folders work the same way. If a kubeconfig refers to files in another folder (for example ~/.minikube), the cluster shows Needs access, and Grant Folder… lets you allow that folder. You can add or remove folders at any time in Settings, Moorings.

Clusters that sign in with a command-line plugin

Many EKS, GKE and AKS kubeconfigs do not hold a token. They name a program (aws, gke-gcloud-auth-plugin, kubelogin) that Wheelhouse is expected to run to get a short-lived credential. The sandbox does not allow the App Store edition to run those programs. A context like that shows this message and cannot be added:

Uses aws (exec plugin). The App Store edition can’t run credential plugins.

The message names the program from your kubeconfig, so it may say gke-gcloud-auth-plugin or kubelogin instead. You have two options:

  • Use a kubeconfig with a service-account token. Create a service account for Wheelhouse, give it the role you want (a read-only view role is a good start), create a token for it and put the token in a kubeconfig user. A token kubeconfig works fully in the App Store edition. Prefer a short-lived token and rotate it.
  • Use the open-source edition. It runs credential plugins as before.

Helm in the App Store edition

Chart Room reads Helm releases straight from the cluster, so you can browse releases, their history, values and manifests, and compare two revisions. It does not install, upgrade, roll back or uninstall, and it has no repository list, because those actions run the helm program. Where a button would be, Chart Room shows a short note and a link to this page.

Using both editions

You can install both on the same Mac. They have different bundle identifiers, and each keeps its own settings, its own Anthropic key and its own list of folders. They do not interfere with each other. Widgets and links open the edition they belong to.

Clusters can sync through iCloud Keychain, like the iPhone and iPad app, if you turn it on for them. Clusters found in kubeconfig files are found separately by each edition.
